## 2024-05-13 - IndexedDB Memory Pressure & Schema Safety
**Learning:** The application extensively uses `.getAll()` on IndexedDB stores that contain large base64-encoded photo strings, even when only counts or metadata are needed. This causes significant memory pressure and UI lag as the dataset grows. Additionally, optimizing these calls requires strict safety checks for object store and index existence, as the single-file nature of the app means users might be on varying schema versions.
**Action:** Always prefer `.count()` or `openKeyCursor()` for statistics and counting. When optimizing IndexedDB access, verify store/index existence via `db.objectStoreNames.contains()` or `store.indexNames.contains()` before opening transactions or accessing indexes to prevent application crashes on older schemas.
