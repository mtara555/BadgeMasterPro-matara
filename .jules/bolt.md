## 2025-05-15 - IndexedDB Blobs & UI Input Bottlenecks
**Learning:** In single-file applications using IndexedDB for storage, storing large base64-encoded photos alongside metadata creates significant memory pressure when using `getAll()`. Even simple tasks like counting records with photos or filtering by event ID can trigger massive memory spikes and slow UI responsiveness if they load all objects. Additionally, high-frequency `oninput` events triggering expensive operations (like QR code generation or full DB re-fetches) without debouncing severely degrade the user experience.
**Action:** Always prefer `count()` or key-only cursors (`openKeyCursor`) over `getAll()` when only counts or specific IDs are needed. Implement debouncing for all UI inputs that trigger non-trivial computations or data fetching.
